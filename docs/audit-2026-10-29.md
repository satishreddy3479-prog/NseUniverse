# Strict audit of the intraday analysis (29 Oct 2026)

Roles taken: data engineer, quant manager, ML engineer, data scientist. Scope: everything built for the intraday engine
(price structure, breakout, VWAP, breadth, flow, IV/Greeks, positioning, labels, evaluation, setups, paper trading, replay, dataset
`if-2`, storage and API surface). Method: read the code, state the invariant it must hold, then try to break it with property tests
on random paths, adversarial inputs, mutation of past/future data, independent re-computation (scipy, finite differences, hand
arithmetic) and the real captured 28 Oct chain. Every defect below has a regression test that fails on the old code.

## Coverage, stated honestly
* Read line by line and attacked: `price_structure`, `vwap`, `volatility`, `positioning`, `labels`, `evaluate`, `setups`, `paper`,
  `costs`, `enrich`, `dataset` joins, `replay`/`research`/`paper` service paths, `market/flow`, `participation`, `weights`,
  `technical`, new API routes, new store methods.
* Read in the parts that feed the new code, not re-audited end to end: `intraday/sentiment.py` (components, assess), `features.py`
  (price features, daily context), `market/metrics.py`, `market/service.py` summary paths. These keep their earlier tests.
* Not re-audited: broker adapter, stream manager internals, archive/backup/EOD mechanics (existing suites pass; EOD gained tests).
* Nothing here has met live Kotak data. That is the largest remaining risk and is listed below.

## Verified correct (with the evidence)
* Black-76 price against a hand-solved value (7.9656); implied volatility round-trips at four volatilities and both sides; delta,
  gamma, vega, theta against central finite differences; forward recovered by put-call parity; on the real 28 Oct chain ATM IV
  16.5 %, forward 22703.85, straddle / one-sd move = 0.80 as theory says.
* The pure-Python logistic model against scipy's L-BFGS optimum of the same regularised loss: loss within 0.002, probabilities within 0.0002.
* Log loss, Brier score, balanced accuracy, confusion, calibration bins, sign test: hand values.
* Barrier labels: read only later samples (rewriting the past does not change a label), first touch wins, gaps give `ambiguous`,
  short coverage gives `missing`; join between stored feature rows and stored paths checked end to end.
* Walk-forward: each test session is predicted only by models fitted on earlier sessions (spy test); a pure coin never beats the
  majority baseline and never passes the gate.
* Cost model: sell-leg STT/brokerage/exchange/SEBI/GST by hand; net = gross - charges - slippage on every simulated trade.
* Paper trading invariants on 10 random paths: fills after signals, one trade at a time, one per setup and direction, trade and
  daily-loss limits respected, reward/risk at the fill price.
* Replay at 10:00 equals the live view at 10:00 for assessment, price, options, regime, scenarios, levels, volatility,
  positioning, structure and setups; replay writes nothing to the score ledger.
* Flow classification conserves volume: buy + sell + unclassified = traded volume since the first push.
* Dataset `if-2`: features of row i do not change when later market recordings change.

## Known limitations (not defects; each is disclosed in the product or this file)
1. **Never run on live Kotak data**: depth message fields, the future's average traded price as day VWAP, the F&O scrip master
   columns, tick rates and server load are unverified. Live checks: `/api/market/coverage`, `/api/market/status`.
2. Implied volatility uses calendar-time annualisation; realised volatility uses trading-time; for these horizons they are within
   about 3 %, but the "IV minus realised" figure is indicative.
3. Barrier size scales the 60-session daily sd by sqrt(h/375), treating all daily variance as intraday; it overstates intraday
   volatility a little, so "none" is over-represented.
4. Weights are rolled forward with NSE's closing price while the page's weights use the last traded price: a small basis error until
   the next official file. Index review dates (March, September) are flagged only by age (60 days).
5. Option LTPs can be stale at an illiquid strike; the parity forward uses the strike nearest spot, which is liquid, but quote time is
   not checked per contract (the feed has none we store).
6. Candles are sampled (about one per minute); highs and lows are sampled extremes.
7. Minute samples overlap: the evaluation counts sessions, not rows, as independent units, but 60 sessions is a small sample.
8. Paper trading proxies the future by the index path and covers only the opening-range rules; VWAP and flow setups cannot be
   back-tested until the futures recordings exist. Cost parameters other than futures STT are assumptions to replace from the
   broker contract note.
9. No rate limiting or authentication on read endpoints (existing architecture); heavy endpoints are cached and serialised.
10. `market.sqlite3` is append-only and grows about 1 MB a day (about 0.3 GB a year); fine for the 15 GB server, worth watching.
