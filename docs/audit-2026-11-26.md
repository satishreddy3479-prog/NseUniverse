# Audit, 26 Nov 2026

Scope: backend (181 modules, 38,291 lines), frontend (214 files, 33,964 lines), the production server, and one full market session of logs (26 Nov, 09:00-16:00 IST). Nothing was changed on the server and no code was changed by the audit.

## How it was done (and what that does and does not cover)

| Method | Covers |
|---|---|
| ruff with bug, security, async, complexity and style rule families; mypy; bandit; vulture; radon | Every backend module, automatically |
| Reading every one of bandit's 28 SQL and 5 URL findings in context | All of them are fixed text, bound values or placeholders (all already marked with a reason) |
| An AST scan of every `async def` for calls that can block the event loop | Every backend module |
| `pip-audit` on `requirements.txt`, `npm audit`, a secrets scan of tracked files | All dependencies and tracked files |
| Reading in full or in large part: stream manager hand-off, snapshot capture, sampler, market service per-tick path, broker adapter, access control, preferences endpoint, Caddy config | The code that carries live data and the front door |
| Server inspection (read-only): request log, app log, sampling continuity, ports, firewall, SSH, timers, backups, updates | The running system |
| Frontend pattern scans (unsafe APIs, listener and timer cleanup, polling, bundle and file sizes) | Every frontend file, by pattern, not by reading |

Not done: reading every function of every module (about 72,000 lines); line coverage (no coverage tool is installed); a browser performance profile of the frontend; a load test. Findings by cause below that come from stack sampling are estimates.

## What is in good shape

- **Data capture:** 386 samples for each expiry against about 385 expected, median gap 60 s, no gap over 90 s, no feed reconnects.
- **No order code anywhere:** the broker adapter only logs in, lists expiries, reads the option chain and scrip master, and opens the feed.
- **Dependencies:** pip-audit on the requirements and npm audit: no known vulnerabilities.
- **Secrets:** none in tracked files; `backend/.env` is git-ignored.
- **SQL:** every dynamically built statement uses constants or `?` placeholders.
- **Input bounds:** preferences are limited to 64 kB a value and 400 keys; control endpoints need a loopback client and an allowed Origin.
- **Front door:** HTTPS, a login on everything except the install files, security headers and a content policy; the firewall allows only 22, 80 and 443; SSH is key-only in effect; fail2ban is active; the clock is synchronised; nightly backups of 19 databases run.
- **Tests:** only 2 backend modules are never referenced by a test.
- **Frontend:** no `innerHTML`, `eval`, `@ts-ignore`; listeners and timers have matching cleanups.

## Findings

### High (they cause the lags seen in market hours)
1. **Per-tick lookups are rebuilt on the event loop every minute, through one locked database connection.** `market/service.py` `_flow_roles`, `_fo_roles`, `_fut_key` and `is_nifty_future_key` cache for 60 s, and the first tick after expiry rebuilds them on the loop: `stream_tokens` reads every token, `universe` rebuilds, `weights_now` scans the whole daily table. 24 of 216 stalls were exactly 60 s apart, and the stack samples show these reads. Fix: build the role maps in the minute loop (a thread) and publish an immutable snapshot; the tick handler only reads it.
2. **The Kotak SDK decodes every packet inside our loop** (pydantic per message): about 43% of the stalls that remain after the 10:07 logging fix (217, none over 2 s). Fix: run the feed and its decoding in its own process or thread and hand over the latest prices in batches.
3. **The Edge report computes on request when cold: 156 s once.** It should be served from the nightly result only.
4. **Stored samples come from REST, 5.4 s after the minute at the median (p99 14.6 s, worst 43.8 s), 770 broker calls a day.** The live feed already holds the same prices. A failed capture is a lost minute (retry after 10 s, then 20, 40...). Fix: build the sample from the feed at :00, with REST as a cross-check and fallback; run it in shadow mode for a few sessions first.

### Medium
5. **One shared SQLite connection with a Python lock per store** (`check_same_thread=False` in 12 stores): readers wait for writers and for each other, so one long query blocks the per-tick lookups. WAL allows concurrent readers; use read-only connections per thread.
6. **Heavy reads are recomputed per request**: strike series (about 0.4 s idle, 2.7 s median in market hours), outlook, risk grid, IV momentum (9 s median), plus about 100 polling timers in the frontend. Cache by (endpoint, arguments, newest sample) with one computation shared by every caller.
7. **Seven small blocking calls on the loop**: `risk_routes._default_expiries` (`store.list(limit=200)`), `forward/service.tick` (`add_run` twice), `market/service.refresh_tokens` (`save_tokens`), `sampler._sample` (`record_event`), `servermgmt/api.storage_snapshot`, `routes.swing_paper_run` (`status`). Move to threads.
8. **`normalize_option_chain`, `core_holes`, `_checked` and `fingerprint` run on the loop** twice a minute at capture (complexity 26). Move to a thread.
9. **SSH config contradicts itself:** `/etc/ssh/sshd_config.d/99-ctrl.conf` (28 Oct) sets `PermitRootLogin yes` and `PasswordAuthentication yes`. The effective settings are safe (`sshd -T`: password login off, root by key only) only because `00-nse-hardening.conf` sorts first. Remove or neutralise `99-ctrl.conf`.
10. **Backups are on the same disk** and the restore check is not scheduled (only the backup and monitor timers are installed). The off-server copy is a manual weekly script. Install the restore-check timer and pull a copy off the server automatically.
11. **One shared login guards every control endpoint**, because the app trusts the proxy's loopback address. Anyone with that login can run control actions. Consider a separate control credential or token for the state-changing endpoints.
12. **Untrusted RSS parsed with the standard XML library** (`globalmkts/news.py:115`): a hostile feed could use entity expansion. Use `defusedxml` or cap the size. Low likelihood (fixed HTTPS feeds).

### Low
13. **Complexity hotspots:** 62 functions over the complexity limit; worst `fusion.capabilities` (93), `fusion.divergences` (53), `forward.engine.step` (46), `analytics.oi.strike_series` (37). They have tests; they are risky to change.
14. **41 `exhaustive-deps` disables** in the frontend: possible stale closures.
15. **`date.today()` in `risk_routes._default_expiries`** uses the server's UTC date, so between 00:00 and 05:30 IST it is yesterday.
16. **SHA1 for identifiers** (4 places): harmless, but mark `usedforsecurity=False`.
17. **Log noise:** a delisted Shanghai index symbol (`000001.SS`) fails four times a day; about 900 SSH probe lines a day.
18. **Updates:** 103 packages upgradable (none flagged as security), Caddy 2.11.9 available; unattended upgrades are enabled.
19. **Very large files:** `api/routes.py` (1,650 lines), `StrategyBuilder.tsx` (1,490).
20. **51 unused `noqa` markers and 135 style notes** (raise-vanilla-args).

## Suggested order

1. Findings 1, 3, 7, 8, 15 (small, backend only, can go out after the close), with a per-minute record of CPU, memory, lag and ticks per instrument class.
2. Findings 6, 9, 10 (caching, SSH file, restore check and off-server copy).
3. Finding 4 in shadow mode, then 2 and 5 with the second CPU.
